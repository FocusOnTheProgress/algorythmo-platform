## PR Gate (blocking — zero violations required)

These criteria block merge. CI runs `@axe-core/playwright` on `/crm` and `/crm/pipeline` and fails if any of these are violated at severity `critical` or `serious`.

| # | WCAG Criterion | Level | What to validate |
|---|---|---|---|
| G1 | **1.1.1 Non-text Content** | AA | All channel icons have `aria-label` or `aria-hidden` + adjacent text. Aging chip glyph has `aria-hidden="true"` — state communicated via `aria-label` on the chip. |
| G2 | **1.3.1 Info and Relationships** | AA | Stage columns use `role="list"` + `role="listitem"` for cards. Kanban heading structure is logical (h1 > h2 per section). |
| G3 | **1.3.3 Sensory Characteristics** | AA | Aging states are NOT communicated by color alone — dual-coding: glyph `●/◐/○/—` alongside color (D11). |
| G4 | **1.4.3 Contrast (Minimum)** | AA | All text ≥4.5:1 against background. Cards: `.alg-neutral-100` text on `.alg-neutral-900` bg ≥ 4.5:1 in dark mode. Chip labels pass AA in all 4 states. |
| G5 | **1.4.11 Non-text Contrast** | AA | Chip border/icon ≥3:1 against adjacent color. Focus ring ≥3:1 against background. |
| G6 | **2.1.1 Keyboard** | AA | Every interactive element reachable and operable by keyboard alone. Cards: `tabindex="0"` + `Enter` to open drawer. Menu ⋮: keyboard triggerable. "Mover para…" modal: radio list + Enter to confirm. |
| G7 | **2.1.2 No Keyboard Trap** | AA | Drawer focus trap is intentional (ARIA pattern for dialogs) — Esc exits. Focus returns to trigger. No other traps. |
| G8 | **2.4.3 Focus Order** | AA | Tab order follows visual left-to-right, top-to-bottom within each column. Drawer: first focusable element gets focus on open. |
| G9 | **2.4.7 Focus Visible** | AA | All interactive elements show visible focus indicator (`:focus-visible` ring using `--alg-color-focus-ring` token). |
| G10 | **4.1.2 Name, Role, Value** | AA | Cards: `role="button"`, `aria-label` includes lead name + stage + time + channel. Drawer: `role="dialog"` + `aria-modal="true"` + `aria-labelledby` pointing to heading. Live region: `aria-live="polite"` for move announcements. |

## Roadmap (non-blocking — tracked, not gating)

These will be addressed post-MVP. PRs are NOT blocked by these.

| # | WCAG Criterion | Level | Why deferred |
|---|---|---|---|
| R1 | **2.4.6 Headings and Labels** | AAA | Stage column headings are `<h2>` but semantic hierarchy review is post-MVP. |
| R2 | **1.4.4 Resize Text** | AA | Fluid typography via `clamp()` handles 200% zoom. Manual validation with VoiceOver + Safari at 200% zoom is roadmap. |
| R3 | **2.5.3 Label in Name** | AA | Buttons with icon + text: visible label matches accessible name. Currently not gated — manual review post-MVP. |
| R4 | **Drag-by-keyboard (ARIA 1.2 pattern)** | Best practice | D11 decision: drag-by-keyboard is post-MVP (F4, C4). Fallback "Mover para…" modal covers the functional requirement. Roadmap: replace `vuedraggable` with a solution supporting `aria-grabbed` + arrow key movement. |
| R5 | **2.4.11 Focus Not Obscured (WCAG 2.2)** | AA (2.2) | Toast container (bottom-right) might obscure focused elements in edge cases. Track when WCAG 2.2 is adopted as gate. |
| R6 | **Screen reader manual smoke (VoiceOver + NVDA)** | Manual | `@axe-core` is automated. Full manual smoke with VoiceOver (macOS) + NVDA (Windows) is recommended before founder demo. Not a CI gate. |

## Implementation checklist (Sessão C)

When implementing components, ensure:

- [ ] `LeadCard.vue` — `role="button"` + `tabindex="0"` + full `aria-label` (name, stage, time, channel).
- [ ] `LeadCard.vue` — `Enter` key triggers open-drawer.
- [ ] `LeadAgingChip.vue` — `.alg-chip__glyph` has `aria-hidden="true"`. Chip `aria-label` describes state in words ("Em dia", "Atenção", "Atrasado", "Sem alerta").
- [ ] `KanbanBoard.vue` — `aria-live="polite"` region announces move (format: "Lead {name} movido para {stage}").
- [ ] `StageColumn.vue` — `role="list"` wrapping cards; `role="listitem"` on each card wrapper.
- [ ] `LeadDetailDrawer.vue` — `role="dialog"` + `aria-modal="true"` + `aria-labelledby="{id of heading}"`.
- [ ] `LeadDetailDrawer.vue` — focus trap (Tab loops inside) + Esc closes + focus returns to trigger.
- [ ] `MoveLeadModal.vue` — stage list as `role="radiogroup"` + `role="radio"` items + keyboard confirm.
- [ ] All icons — `aria-hidden="true"` + adjacent visible text OR `aria-label`.
- [ ] Focus rings — `--alg-color-focus-ring` token applied to all `:focus-visible` states.

## Axe-core configuration

The `playwright.config.ts` project `algorythmo-a11y` runs `@axe-core/playwright` with:

```ts
axeOptions: {
  runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa'] },
}
```

Gate: violations with `impact === 'critical' || impact === 'serious'` fail CI.

`moderate` and `minor` violations are reported but do not block merge (they appear in the Playwright HTML report).

## Tokens used for accessible contrast

From `engines/algorythmo/app/assets/stylesheets/_tokens.scss` (PR #37):

| Token | Value | Use |
|---|---|---|
| `--alg-neutral-100` | `oklch(95% 0.005 250)` | Card text (dark mode) |
| `--alg-neutral-900` | `oklch(12% 0.01 250)` | Card background (dark mode) |
| `--alg-color-focus-ring` | `oklch(70% 0.2 250)` | Focus ring (all interactive elements) |
| `--alg-aging-green` | (see tokens) | Chip green state — verify ≥4.5:1 against card bg |
| `--alg-aging-yellow` | (see tokens) | Chip yellow state — verify ≥4.5:1 against card bg |
| `--alg-aging-red` | (see tokens) | Chip red state — verify ≥4.5:1 against card bg |
